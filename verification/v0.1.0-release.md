# Hibermachy v0.1.0 verification record

Release date: 2026-09-27. Release commit: `f1ad0912556b92d88fd088df03aea98fd6a9decd` (identical to v0.1.0-rc.3). GitHub tracking: https://github.com/spitefulFr0g/hibermachy/issues/26

The owner directed publication while skipping further checks that need a human in the loop. This is an experimental public release, not a claim that the attended gate passed. Source archive SHA-256: `ca0f257b279b3555ea72d491802d3f99d2c30726e1e7a1b21ecf77008104e8bb`. Signing fingerprint: `0B1C5414F8D18F8B6AA78957335FEBC82DB247EC`.

## Automated verification

- `npm run test:candidate` passed on the release commit with ShellCheck 0.11.0, 33 Rust tests, formatting, static checks, lifecycle/packaging/traceability/cross-seam tests, and native regressions.
- `npm test` passed on a full retry: all 18 hosted scenarios, the 2,000-transition soak, lifecycle, packaging, native-probe, and hardware-workaround regressions. The first run stopped at the seventh hosted scenario during graphical shell startup without an assertion failure; that scenario passed alone, and the complete retry passed. An intermittent graphical startup failure was observed; its cause was not established, and the first run is not counted as a pass. The hosted matrix simulates sleep; no physical hibernation is inferred.
- A source package was built from the published rc.3 URL with signature and checksum verification; installed helper and Polkit policy matched the public build. After publication, a fresh source package build fetched the archive and signature from the stable v0.1.0 URL, passed SHA-512 and OpenPGP verification, and produced helper and Polkit files byte-identical to those installed. No prebuilt root executable was published.

## Attended evidence

- `system-inhibitor`: PASS. The runtime refused a staged-sleep request with `HBR-SLEEP-SYSTEM-INHIBITED` and submitted no sleep transaction.
- `reload-while-latched`: PASS. Reload did not submit a sleep transaction while the latch was set.
- `early-wake`: PASS for early wake only. A 91-second suspend interval returned to the same session, with successful systemd transaction and restored IPTS/Wi-Fi guards. The runtime made no hibernation claim.
- `Stay Awake`, `compositor-inhibition`, `fresh-activity`, `suspend-fallback`: NOT COMPLETED as attended cases. A partial fresh-activity preparation showed no submission but did not complete the timed case.
- Required full staged-sleep/observed-hibernation/same-session-resume cycles: **0 of 3**. Automatic, manual, and AC-disconnect coverage not established.
- The attended procedure was stopped. The original user policy (automatic enabled, idle delay 300 seconds), requested and effective system policy (hibernate delay 3600 seconds, hibernate on AC power), and Stay Awake on were restored and verified; the user-policy revision advanced from 4 to 8 as a result of preparation and restoration. No sleep transaction was in progress at final verification.

The candidate was exercised on the designated existing machine running Omarchy 4.0.4-1, Quickshell 0.3.1, and systemd 261.2-1. This exact combination is an **unverified environment** for physical staged sleep. Clean-environment and assistive-technology qualification were accepted as unmet by the owner. Independent code review was by agents, not humans.
