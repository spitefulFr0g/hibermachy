Release date: 2026-09-28. Release commit: `c09a191fbaabf9bd0ac246715afe408ebe62c5ce` (identical to v0.1.1-rc.4). GitHub tracking: https://github.com/spitefulFr0g/hibermachy/issues/26

## Changes since v0.1.0

- #55 (PR #56): the inhibitor-aware idle monitor now activates from policy state, so a live Wayland idle inhibitor produces the automatic `HBR-COMPOSITOR-IDLE-INHIBITED` blocker.
- #57 (PR #58): a returned suspend-only fallback is recorded as `Degraded` / `HBR-SLEEP-SUSPEND-FALLBACK`, as spec #2 requires, instead of `Completed`.

## Automated verification

- `npm test` passed on the release commit: the hosted Quattro scenarios, the real Wayland inhibitor regression, the new production-path fallback regression (`HBR-CHK-OBSERVED-FALLBACK-001`), lifecycle, packaging, traceability, native-probe, evidence-observer and hardware-workaround regressions. The hosted matrix simulates sleep; no physical hibernation is inferred.
- `npm run test:candidate` passed. ShellCheck was not installed and was reported as an environment limit; the ShellCheck step did not run.
- Independent code review of the #57 change was by agents, not humans.
- The helper source package was built from the published rc.4 recipe after an anonymous download, with SHA-512 and OpenPGP verification. The extracted source passed `omarchy plugin validate`. No prebuilt root executable is published.

## Attended evidence

These cases ran on the designated machine against v0.1.1-rc.3 (`5f9081d`). rc.4 differs from rc.3 only by the #57 change to fallback outcome reporting and its regression test, and neither touches these paths.

- `compositor-inhibition`: PASS. Stay Awake was off and a fullscreen video client held a confirmed Wayland idle inhibitor for 351 seconds with no input. Every sample reported `HBR-COMPOSITOR-IDLE-INHIBITED`, the idle deadline was not reached, no request was submitted, and the sleep journal and outcome history were unchanged. The operator physically observed the machine awake throughout. An earlier attempt was invalid: the operator folded the Type Cover, and the platform's own lid-switch action suspended the machine for 8 seconds. Hibermachy made no request during that attempt.
- `Stay Awake suppression`: PASS. Stay Awake was on for 317 seconds and every sample reported `HBR-STAY-AWAKE-ENABLED`. The operator physically observed the machine awake throughout, and there was no request or sleep.
- `system-inhibitor`: PASS. A manual request with a logind block inhibitor was refused with `HBR-SLEEP-SYSTEM-INHIBITED`, and no systemd sleep transaction occurred.
- `fresh-activity re-arm`, `reload while latched`, `early wake`, `deliberate suspend fallback`: **NOT RUN for v0.1.1**. They are waived by owner determination. Automated coverage and code inspection only. On v0.1.0, `reload-while-latched` and `early-wake` passed as attended cases on different bits.
- Owner determination for early wake: the expected result is `Completed` / `HBR-SLEEP-TRANSACTION-RETURNED` with hibernation not confirmed and the re-arm latch held. The obsolete `HBR-SLEEP-EARLY-WAKE` expectation is superseded because only the test simulator emits it.
- Required staged-sleep, observed hibernation and same-session resume cycles: **0 of 3**. Waived by owner determination. Automatic, manual and AC-disconnect coverage is not established. Physical hibernation with this release is unverified.
- After the attended run, the original user policy (automatic enabled, idle delay 300 seconds), requested and effective system policy (hibernate delay 3600 seconds, hibernate on AC power) and Stay Awake on were restored. Configuration was verified byte for byte against pre-run snapshots.

The candidate was exercised on the designated existing machine running Omarchy 4.0.4-1, Quickshell 0.3.1-1 and systemd 261.2-1. This combination is an **unverified environment** for physical staged sleep. Clean-environment and assistive-technology qualification remain accepted unmet by earlier owner determinations. No general compatibility, hardware, security or accessibility certification is claimed.

Published assets are not to be replaced for this version. A defect found later will be corrected only in a new release.
