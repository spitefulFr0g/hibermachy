# Hibermachy v0.1.2 verification record

Release date: 2026-09-28. Release commit: `d1dc524d23529ab7e1ea43c975f3b5b3b57aaf57` (identical to v0.1.2-rc.2). Tree: `92d6e380c545901743066944874018aacc653d6d`. GitHub tracking: https://github.com/spitefulFr0g/hibermachy/issues/48

This is an experimental release. It changes installation and updates only; staged-sleep behavior is unchanged from v0.1.1. It does not claim that the attended hardware gate passed: physical hibernation remains **unverified**, and the waived v0.1.1 requirements remain accepted unmet, not passed. Source archive SHA-256: `8c38d56ae92d4584570e6cfc4f61e6e636e9a9bef2e797424a1629edab8df8a1`, byte-identical to the rc.2 archive, so the rc.2 signature is reused. Signing fingerprint: `0B1C5414F8D18F8B6AA78957335FEBC82DB247EC`.

## Changes since v0.1.1

- #48 (PR #60): `setup` and `update` run from the extracted, signature-verified release with `--recipe <dir>`.
  - The recipe must name the pinned key and this version.
  - The extracted source and the plugin checkout's release tag must have the same Git tree as the signed archive.
  - The checkout is added disabled and pinned to the release tag.
  - The helper is built under `~/.cache/hibermachy`, never inside the checkout.
  - The PR also adds an MIT license and a single root manifest, removes historical `handoff/` and `.scratch/` records from the tree, and documents install, update, removal and recovery in the README.
- #48 (PR #61), from a fresh-install rehearsal of rc.1:
  - A failed helper build reports `HBR-LIFECYCLE-MAKEPKG-FAILED` instead of a cleanup permission error.
  - A missing Rust toolchain is refused early with `HBR-BUILD-TOOLCHAIN-NOT-READY`.
  - In a terminal, commands end with a one-line summary.
  - Download verification prints no progress meters.
  - No debug package is built.

## Automated verification

- Full `npm test` passed on `a9f2ad7`. `npm run test:candidate` and the lifecycle-production tests passed on the release commit. ShellCheck was not installed and was reported as an environment limit.
- `tests/lifecycle_production.sh` covers these cases with a realistic `git archive` release and a local remote:
  - A tampered archive, a modified bootstrap and a moved tag.
  - `main` moving past the release.
  - A retry without `shell.json`.
  - Refusal while active.
  - Update, and a build failure with recovery.
  - A dirty checkout.
  - The missing toolchain.
  - The terminal summary.
  - Uninstall and purge.
- Agents, not humans, reviewed both PRs independently. Their findings were fixed before merge.
- The marketplace validator (run locally on `50c261c`) reported "Ready for listing review". The marketplace security baseline reported `review-required` with no findings. No marketplace submission has been made.

## Install evidence

- **Fresh-install rehearsal, agent-run on the designated machine.** This is not a clean environment. It used an isolated `HOME`, a fresh GnuPG keyring and anonymous downloads, and followed the README commands for rc.2.
  - Checksums, fingerprint, signature and `omarchy plugin validate` passed.
  - Without a Rust toolchain, setup refused with `HBR-BUILD-TOOLCHAIN-NOT-READY` and added nothing.
  - With a toolchain, setup did the following:
    - It added the plugin disabled.
    - It pinned the checkout to the rc.2 tag, detached and clean.
    - It built only the main helper package and emptied its build directory.
    - It stopped at `sudo pacman -U` for lack of a terminal, reporting `HBR-LIFECYCLE-MAKEPKG-FAILED`.
- **Fresh install on a second computer, owner-run, from rc.2 following the README.** The computer had no Hibermachy plugin, helper package or activation before the install. It is not a clean environment: other plugins were installed.
  - Setup installed `hibermachy-helper 0.1.2-1` through pacman.
  - After `activate --confirm`, `status` reported the plugin enabled. Checkout, activation, menu contribution, helper package, runtime dependencies, live readiness, user configuration and outcome history were all `compatible`.
  - Requested and effective system policy were `missing`, as expected, since no hibernate delay had been set.
  - Omarchy 4.0.4-1, Quickshell 0.3.1-1: the same versions as the designated machine.
  - Opening the panel and setting a hibernate delay through the new helper were not reported, so they are **not recorded as tested**.
- **Upgrade from v0.1.1 on the designated machine, owner-run.** Before the update, v0.1.1 was installed and enabled, with a Hibermachy system policy in place. The owner ran `update` from rc.2.
  - Afterwards the plugin was enabled.
  - The checkout was detached with a tree equal to rc.2, and it had no local changes.
  - The helper was `0.1.2-1`, and every `status` scope was `compatible`.
  - No update intent remained, and the build cache was empty.
  - The existing policy (`HibernateDelaySec=3600s`, `HibernateOnACPower=yes`) was unchanged.
- **Not run on hardware:** `remove`, `uninstall`, `purge`, recovery after a failed update, and updating from v0.1.2 to a later release. Only automated coverage exists for these.

No general compatibility, hardware, security or accessibility certification is claimed. Published assets are not to be replaced for this version. A defect found later will be corrected only in a new release.
